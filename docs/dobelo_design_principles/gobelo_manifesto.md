# Gobelo Design Principles Manifesto

## A Manifesto for Language Technology in Resource-Constrained Contexts

Gobelo is founded on a simple but powerful conviction:

> **Linguistic intelligence belongs in structured grammar data, not procedural code.**

Language technology should not be constrained by engineering bottlenecks, hardcoded assumptions, or narrow linguistic coverage. Instead, systems should be built to grow through knowledge, collaboration, and structured linguistic representation.

We therefore commit to the following principles.

## 1. Grammar Over Code

Language behavior must be defined through structured linguistic knowledge rather than embedded procedural logic.

Gobelo treats grammars as first-class citizens. Linguistic systems should be transparent, inspectable, and editable by domain experts.

## 2. Languages Without Reengineering

Adding a language should require data—not rewriting software.

Gobelo is intentionally language-agnostic. New languages should integrate through grammar definitions and registration rather than core code modification.

## 3. Modular Responsibility

Each component should do one thing well.

Responsibilities must remain clear, bounded, and composable. No subsystem should know more than it needs to know.

## 4. Stable and Safe Interfaces

Public contracts matter.

Interfaces should be typed, predictable, explicit, and stable over time to support sustainable ecosystem growth.

## 5. Reliability Through Explicit Failure

Systems should fail clearly rather than fail silently.

Errors are signals for learning, diagnosis, and improvement—not events to hide.

## 6. Frugal and Sustainable Engineering

High linguistic impact should not require excessive engineering cost.

Gobelo prioritizes reuse, efficiency, low-maintenance expansion, and scalable linguistic coverage.

## 7. Participation by Design

Language experts should be able to contribute without becoming software engineers.

Gobelo is built for interdisciplinary collaboration between linguists, educators, communities, and developers.

## Closing Principle

Gobelo exists to make language technology:

- more inclusive  
- more extensible  
- more sustainable  
- more collaborative  

because language preservation and language technology should scale through shared knowledge—not duplicated engineering effort.
